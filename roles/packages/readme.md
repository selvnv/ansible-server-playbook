Ansible использует понятие контекста роли. Это контекст выполнения задач, который, в частности, определяет, где Ansible ищет связанные с ролью файлы (`templates/`, `files/` и т. д.). Контекст роли устанавливается Ansible автоматически при выполнении роли через `roles:`, `include_role` или другие механизмы запуска роли.

Контекст роли — это контекст выполнения, в котором Ansible знает текущую роль и использует её каталоги (`templates/`, `files/` и т. д.) при поиске файлов

`defaults/` - переменные роли по умолчнию; имеют самый низкий приоритет (переопределяются переменными хоста/группы из инвентаря, и другими более приоритетными переменными)
`tasks/` - содержит точку входа для запуска роли по умолчанию - `main.yml`, остальные таски вызываются из `main.yml` через `import_tasks`
`templates/` - содержит jinja2-шаблоны, которые используются модулем `ansible.builtin.template`
- используется как стандартное место для поиска файлов-шаблонов, если указан относительный путь к файлу 
- можно переопределить путь поиска, указав абсолютный путь к файлу
`files/` - содержит обычные статические файлы, не требующие рендера (по умолчанию, `ansible.builtin.copy` ищет файлы именно тут)
- используется некоторыми модулями (например, `copy` или `unarchive`) как одно из стандартных мест поиска файлов при вызове внутри роли
- можно переопределить путь поиска, указав абсолютный путь к файлу
